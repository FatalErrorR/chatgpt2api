# 前端重设计 · 开发计划

设计稿：`docs/design/anthropic-redesign.html`（号池采用方案 B）。

## 边界

- **只改前端**：所有改动限定在 `web/` 目录（以及 `docs/`）。不改后端代码、接口、配置格式和业务逻辑。
- **只用现有接口**：页面需要的数据全部来自现有 API（`web/src/lib/api.ts` 已有的函数）。若某个设计需要新接口，则降级为现有接口能实现的样子，而不是加接口。
- **行为不变**：筛选、批量操作、导入、代理分配、生图参数等功能的结果与现在一致，只换外观和布局。
- **每批自检**：合并前执行
  `git diff --stat main...<分支> -- . ':(exclude)web' ':(exclude)docs'`，输出必须为空。

## 验收（每批都要过）

1. `npx tsc --noEmit -p .`、`node --test test/*.test.ts`、`npx next build` 全部通过（CI 的 web 任务自动跑）。
2. Python 测试不受影响（CI 的 python 任务自动跑）。
3. 本地启动后端 + 前端，逐页截图对照设计稿；浅色、深色、窄屏（390px）各看一遍。
4. 每批单独提交、合并、部署，部署前征得同意；出问题可单独回滚这一批的镜像。

已知的坑：

- 深色下 `bg-ink` 是浅色。叠在它上面的东西（批量操作条）不能写死浅色字；深色主题的 `--bad` 是浅粉，在浅底上要用 `#B5483B`。
- 深色去阴影规则只跳过 `shadow-[inset…]`，选中框、状态线必须用 inset 阴影画。
- `test/dark-theme.test.ts` 会拦住 `bg-stone-950/900 + text-white` 的按钮和批量条上写死的浅红字。
- 大图预览里叠在照片上的半透明白按钮（`bg-white/10`、图片管理的 `hover:bg-white`）是叠层，不是页面底色。
